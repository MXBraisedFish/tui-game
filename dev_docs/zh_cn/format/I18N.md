# 国际化语言结构规范

## 前言

国际化语言旨在保证多语言的适配，让不同国家和地区的玩家在阅读文本时无障碍。使用 API 创建国际化语言必须遵循严格的目录结构与数据结构，本文档将详细介绍。

## 目录结构

国际化语言要求使用特定的资源目录结构，所有语言文件必须统一存放在 `assets/language/` 目录下，并按语言代码划分子目录，每个子目录内放置以命名空间命名的 JSON 文件。

```text
assets/
- language/
  + [language_code]/
  | + [namespace].json
  | - ...
  - ...
```

| 可变文件名      | 说明     |
| --------------- | -------- |
| [language_code] | 语言代码 |
| [namespace]     | 命名空间 |

### 示例

**正确结构**

```text
assets/
- language/
  + zh_cn/
  | + home.json
  | - setting.json
  - en_us/
    + home.json
    - setting.json
```

**错误结构**

> 无语言代码目录

```text
assets/
- language/
  + home.json
  - setting.json
```

> 未放在指定的根目录 `language/` 下

```text
assets/
- i18n/
  - zh_cn/
    + home.json
    - setting.json
```

> 过度嵌套目录

```text
assets/
- i18n/
  - zh_cn/
    - home/
      - start.json
```

## 文件结构

每个命名空间文件必须是 JSON 格式，且内容为单层键值对，所有值必须为字符串类型。

```json
test.json

{
  "key": "value",
  ...
}
```

### 示例

**正确结构**

```json
i18n.json

{
  "home.title": "This is a Title",
  "home.start": "Start Game!"
}
```

**错误结构**

> 非 JSON 文件

```text
home.txt
```

> 值的类型错误

```json
{
  "coin": 10,
  "fruit": ["banner", "apple"]
}
```

> 过度嵌套

```json
{
  "player": {
    "p1": "Peter",
    "p2": "Alice"
  }
}
```

## API 的使用

在脚本开发中，可通过 i18n 库提供的 API 构建国际化语言实例，快速匹配系统语言设置，并提供高效的文本查询与回退机制。

详细 API 可查看文档⌊[i18n](api/i18n.md)⌉。

## 基础教程

**前提**：系统所使用的语言为中文，语言代码为 zh_cn

**步骤 1：创建资源文件**

按规范创建目录及 JSON 文件，例如：

目录：

```text
assets/
- language
  + zh_cn/
  | - test.json
  - en_us/
    - test.json
```

写入内容：

```json
zh_cn/test.json

{
  "title": "标题",
  "setting": "设置"
}
```

```json
en_us/test.json

{
  "title": "Title",
  "setting": "Setting",
  "start": "Start"
}
```

**步骤 2：在脚本中实例化**

在 `Init` 回调中调用 `i18n.create`，无参构造将自动使用系统当前语言作为首选，并默认使用 en_us 作为备用语言。

> 注意：create 为单例模式，全局仅生效一次，重复调用将被忽略。

```lua
function Init(ctx)
  i18n.create {} -- 无参构造
  -- 等价于
  i18n.create { language_code = "zh_cn", callback_language_code = "en_us" } -- 表参数构造
end
```

**步骤 3：监听实例化完成事件**

由于 `i18n.create` 涉及磁盘读取，操作为异步，完成后会触发类型为 "i18n" 的事件，可通过事件回调接收结果。

事件返回，请查看⌊[事件结构](../EVENT.md)⌉文档⌊i18n⌉部分。

```lua
function HandleEvent(event)
  if event.type == "i18n" and event.data.ok then
    debug.print { message = "I18N Get!" }
  end
end
```

输出：

```text
I18N Get!
```

**步骤 4：查询文本**

实例化完成后，即可使用 `i18n.get_value` 按命名空间和键名获取对应语言文本。

```lua
value = i18n.get_value { namespace = "test", key = "title"}
debug.print { message = value }
```

输出：

```text
标题
```

**步骤 5：回退机制与缺失键处理**

当查询的键在当前语言中不存在时，系统会依次尝试以下回退路径：

- **优先回退**：使用参数 `callback_language_code` 指定的备用语言（默认为 `en_us`）查找。
- **最终回退**：若备用语言中也找不到，则返回带有键名的缺失提示。

**优先回退**

```lua
value = i18n.get_value { namespace = "test", key = "start"} -- zh_cn/test.json 中无该键
debug.print { message = value }
```

输出：

```text
Strat
```

**最终回退**

若回退语言也不存在相应的值，则返回缺失键提示

```lua
value = i18n.get_value { namespace = "test", key = "about"} -- zh_cn/test.json 和 en_us/test.json 中均无该键
debug.print { message = value }
```

输出：

```text
[缺少 i18n 键：test.about]
```

## 进阶教程

**1. 获取当前语言代码**

若需根据系统语言动态加载其他资源，可使用 `i18n.get_language_code` 获取当前系统所生效的语言代码。

```lua
code = i18n.get_language_code()
debug.print { message = code }
```

输出：

```text
zh_cn
```

**2. 自定义语言切换与热重载**

如果开发时，想自行实现语言选择和热切换，可以使用相关 API 组合完成

事件返回，请查看⌊[事件结构](../EVENT.md)⌉文档⌊i18n⌉部分。

```lua
local i18n = false -- i18n 是否已加载完成标志位

local function reload_i18n(code)
  i18n = false -- 重置标志位为未完成

  i18n.reload { language_code = code } -- 重载实例
end

function Init(ctx)
  i18n.create {} -- 初始化
end

function HandleEvent(event)
  if event.type == "i18n" and event.data.ok then
    i18n = true -- 标记为已完成
  end
end
```

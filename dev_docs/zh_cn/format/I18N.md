# 国际化语言结构规范

## 前言

国际化语言旨在保证多语言的适配，让不同国家和地区的玩家在阅读文本时无障碍。使用 API 创建国际化语言必须遵循严格的目录结构与数据结构，本文档将详细介绍。

## 目录结构

国际化语言要求使用特定的资源目录结构，所有语言文件必须统一存放在 `assets/language/` 目录下，并按语言代码划分子目录，每个子目录内放置以命名空间命名的 JSON 文件。

```text
assets/
- language/
  + [language_code]/
  | + [namespace].json
  | - ...
  - ...
```

| 可变文件名      | 说明     |
| --------------- | -------- |
| [language_code] | 语言代码 |
| [namespace]     | 命名空间 |

### 示例

**正确结构**

```text
assets/
- language/
  + zh_cn/
  | + home.json
  | - setting.json
  - en_us/
    + home.json
    - setting.json
```

**错误结构**

> 无语言代码目录

```text
assets/
- language/
  + home.json
  - setting.json
```

> 未放在指定的根目录 `language/` 下

```text
assets/
- i18n/
  - zh_cn/
    + home.json
    - setting.json
```

> 过度嵌套目录

```text
assets/
- i18n/
  - zh_cn/
    - home/
      - start.json
```

## 文件结构

每个命名空间文件必须是 JSON 格式，且内容为单层键值对，所有值必须为字符串类型。

```json
test.json

{
  "key": "value",
  ...
}
```

### 示例

**正确结构**

```json
i18n.json

{
  "home.title": "This is a Title",
  "home.start": "Start Game!"
}
```

**错误结构**

> 非 JSON 文件

```text
home.txt
```

> 值的类型错误

```json
{
  "coin": 10,
  "fruit": ["banner", "apple"]
}
```

> 过度嵌套

```json
{
  "player": {
    "p1": "Peter",
    "p2": "Alice"
  }
}
```

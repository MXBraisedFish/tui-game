## file

| 项目       | 当前规则                                                                                  |
| ---------- | ----------------------------------------------------------------------------------------- |
| 脚本权限   | 仅游戏脚本可写，屏保脚本禁止；不要求开启调试模式                                          |
| 写入范围   | 限当前包的 `assets/`，解析后的路径必须仍在该目录内                                        |
| 路径格式   | 禁止绝对路径、`..`、空路径、NUL；路径最长 **8192 字节**                                   |
| 文件名     | 拒绝 Windows 保留设备名、非法字符，以及以空格或点结尾的路径段                             |
| 目标类型   | 父目录必须存在且为目录；允许创建新文件，禁止把目录当文件写入                              |
| 内容大小   | 输入最多 **1 MiB**；文本转换编码和换行后，输出仍不得超过 **1 MiB**                        |
| 文本模式   | 输入必须是有效 UTF-8、不能包含 NUL；过多异常控制字符会被判为二进制数据并拒绝              |
| 编码转换   | 不能无损编码时失败，不会静默替换无法表示的字符                                            |
| 二进制模式 | 允许任意字节，包括 NUL；忽略编码和换行参数                                                |
| 请求数量   | 每个 Session 最多 **8 个未完成文件请求**，读写等操作共用；共享宿主命令队列上限为 **4096** |

参数、路径或请求提交检查失败会同步抛出异常；提交后的磁盘权限不足、编码失败等，通过原有失败事件通知。实现见 [file.rs](E:/Code/tui-game/crates/service/lua/src/api/libraries/file.rs)。

写入采用“临时文件 → 同步磁盘 → 备份旧文件 → 替换”的流程，替换失败时尝试恢复旧文件，并清理临时文件。见 [atomic_fs (line 30)](/E:/Code/tui-game/crates/core/atomic_fs/src/lib.rs:30)。

目前还有几个实际边界：

- 允许覆盖已有文件，没有覆盖确认、扩展名白名单或累计磁盘用量配额。
- 没有同一文件的写入串行锁，多个异步请求同时写同一路径可能发生竞争。
- 路径检查与后台写入分开执行，尚不能完全防御外部程序在两者之间替换目录或链接的竞态。
- 备份恢复属于尽力处理，不能保证断电或进程被强制终止时一定完成恢复。

## math

I：integer 范围 [-9223372036854775808, 9223372036854775807]。
F：有限 float，约为 [-1.7976931348623157×10³⁰⁸, 1.7976931348623157×10³⁰⁸]，不包含 NaN、正负无限。
表中“有限数”表示接受 integer / float。
仅接受 integer 的参数会拒绝 2.0。
计算结果为 NaN 或正负无限时抛出异常；浮点下溢为 0 允许发生。

ldexp 的实际边界需要特别区分：

- x=0：允许任意 I 范围的 exp，直接返回带原符号的零。
- x≠0 且 exp>2097：报溢出异常。
- x≠0 且 exp<-2097：返回带 x 符号的零。
- -2097≤exp≤2097：仍取决于 x，计算结果溢出则报错。
  因此，当前文档里的“x 不得为 0、exp 只能在 [-2097,2097]”与实现并不一致。

另外，多数计算会将 integer 转为双精度浮点数，绝对值超过 2^53 的整数可能失去精度；这与是否越界是两回事。normalize_angle 的 integer 分支、整数取余和整数比较等保留整数运算。

| 方法                     | 数值限制及关系                                                                                            |
| ------------------------ | --------------------------------------------------------------------------------------------------------- |
| `abs`                    | value 为有限数；返回绝对值                                                                                |
| `ceil`、`floor`、`round` | integer 输入接受完整 I；float 输入经对应取整后，结果必须落入 I                                            |
| `round_to`               | value 为有限数；precision 为 integer，范围 `[-308,308]`。正数表示小数位，负数表示整数位；舍入结果必须有限 |
| `fmod`                   | x、y 均为 I 中的 integer，`y≠0`；余数符号与 x 一致                                                        |
| `pow`                    | x、y 为有限数；计算 `x^y`。负底数的指数须为数值上的整数；`0` 的负次幂报错；`0^0=1`；结果必须有限          |
| `exp`                    | 计算 `e^value`；value 须有限，结果有限对应上限约 `709.782712893384`                                       |
| `log`                    | `value>0`；`base>0` 且 `base≠1`；两者均有限；计算 `ln(value)/ln(base)`                                    |
| `lg`、`ln`               | value 为有限正数，不能为 0                                                                                |
| `sqrt`                   | value 为有限数且 `value≥0`，允许 0                                                                        |
| `ldexp`                  | x 为有限数，exp 为 I 中的 integer；计算 `x×2^exp`，详细规则见下                                           |
| `frexp`                  | value 为有限数；满足 `value=mantissa×2^exponent`。非零时 `0.5≤abs(mantissa)<1`；零返回零尾数和零指数      |
| `sin`、`cos`、`tan`      | value 为有限数，单位为弧度；按浮点三角函数计算，没有额外的周期范围限制                                    |
| `asin`、`acos`           | `-1≤value≤1`                                                                                              |
| `atan`                   | value 为有限数                                                                                            |
| `atan2`                  | y、x 均为有限数，允许两者同时为 0；返回角度范围 `[-π,π]`                                                  |
| `deg`                    | value 为有限弧度；计算 `value×180/π`，结果必须有限                                                        |
| `rad`                    | value 为有限角度；计算 `value×π/180`                                                                      |
| `normalize_angle`        | value 为有限数；返回 `[0,360)` 内的角度                                                                   |
| `max`、`min`             | 接受长度 `[1,16384]` 的稠密数组，元素均为有限数；若提供 n，必须为相同范围的 integer，并与数组结构一致     |
| `modf`                   | integer 输入接受完整 I；float 的截断整数部分必须落入 I。返回整数部分和小数部分，二者之和对应原值          |
| `ult`                    | left、right 均为 I 中的 integer；按无符号 64 位整数比较，负数按原二进制位解释                             |
| `approx_equal`           | left、right 为有限数；epsilon 为有限非负数，默认 `1e-10`；判断 `left==right` 或 `abs(left-right)≤epsilon` |
| `ratio`                  | value、total 为有限数，`total≠0`；默认计算 `value/total`，as_percent=true 再乘 100；结果必须有限          |
| `factorial`              | n 为 integer，`0≤n≤170`；返回浮点阶乘，`0!=1`                                                             |
| `combination`            | n、k 为 integer，满足 `0≤k≤n≤I上限`；结果 `C(n,k)` 必须不超过 I 上限                                      |
| `tointeger`              | 接受任意类型；integer 原样返回，float 必须有限、无小数部分且处于 `[-2^63,2^63)`，否则返回 nil             |
| `type`                   | 接受任意类型；integer 返回 `"integer"`，float（包括 NaN、无限）返回 `"float"`，其他返回 nil               |

还有这些行为需要注意：

- 每次 generate 成功后，offset 增加 1；达到上限后继续 generate 会抛异常。
- 相同类型、范围、seed、offset 可重现相同结果。set 修改其他参数时，省略 offset 会保留当前位置。
- INT 默认区间为 `[-2147483648,2147483647]`；FLOAT 默认 `[0,1]`。
- FLOAT 切换为 INT 时，**当前原区间**的两个边界必须无小数且能转换为整数，即使同时提供新 min/max，也会先检查原区间。
- 当前整数参数仍接受 `2.0` 这类无小数的 float；本次未改变类型校验。
- 格式合法但不存在的 ID：generate、get_info 返回 nil；set、delete、exists 返回 false。格式非法的 ID 抛异常。
- randint、randfloat 使用独立的内部生成器，不计入 count/list，clear 不重置其状态。
- 自动 seed 来自时间、进程 ID 和计数器，不适合生成安全令牌。

## serialization

Git 差异中，你对类型的修改有两处，均已保留，没有据此调整实现：

- `yaml_encode.value`：`table / 基本类型 → any`。
- `binary_pack`：新增 `data: any...` 参数行。

**any 不代表所有类型均可序列化，any... 也不代表任意数据都能打包。** 当前实际类型如下。

| 方法 | 参数的实际类型与要求 |
|---|---|
| `json_encode` | value：nil / boolean / integer / 有限 float / UTF-8 string / 可序列化 table / `serialization.NULL` |
| `json_decode` | text：UTF-8 string |
| `csv_encode` | rows：二维稠密数组 table；单元格为 boolean / integer / 有限 float / UTF-8 string |
| `csv_decode` | text：UTF-8 string |
| `yaml_encode` | value：boolean / integer / 有限 float / UTF-8 string / 可序列化 table / `serialization.NULL`；**不接受 nil** |
| `yaml_decode` | text：UTF-8 string |
| `toml_encode` | value：对象 table，根层使用字符串键 |
| `toml_decode` | text：UTF-8 string |
| `ini_encode` | value：对象 table，根层使用字符串键 |
| `ini_decode` | text：UTF-8 string |
| `xml_encode` | value：包含一个命名根元素的 table |
| `xml_decode` | text：UTF-8 string |
| `binary_pack` | format：UTF-8 string；后续数据为格式项要求的 integer / float / string |
| `binary_unpack` | format：UTF-8 string；data：可包含任意字节的 string；选填 position：integer，默认 1 |
| `binary_packsize` | format：UTF-8 string |

除 `binary_pack` 外，当前编码方法都只接受**一个根值**。`binary_pack` 已支持可变参数，数据数量必须匹配格式串；不消耗数据的格式可以传零个数据。

`binary_unpack` 仍返回两个值：`values: table`、`next_position: integer`，没有改为多个数据直接返回。整数参数目前仍接受 `2.0` 这类无小数的 float。

当前库的主要限制：

| 范围 | 限制 |
|---|---|
| 文本 | 解码输入、编码输出上限均为 **1 MiB**；文本格式要求有效 UTF-8 |
| 通用结构转换 | 深度阈值 **32**，累计转换节点最多 **16384**，包含根值和字段值 |
| table | 数组须从 1 开始连续；对象使用字符串键；禁止混合数组与对象键、稀疏数组、循环引用 |
| 不支持的值 | function、thread、普通 userdata 等；`serialization.NULL` 是特殊例外 |
| 数值 | 文本编码拒绝 NaN、正负无限；大整数解码为 float 时可能损失精度 |
| 空表 | 通用转换将 `{}` 识别为对象，不识别为空数组 |
| 执行方式 | 全部同步执行，共享 Session 的内存与回调执行预算，不产生完成事件 |

各格式还有这些区别：

- **JSON／YAML**：支持根层标量和数组。null 解码为 `serialization.NULL`；YAML 拒绝自定义标签及无法转换为 JSON 兼容结构的值。当前 YAML 实际支持的根结构，比格式规范中“必须为对象表”更宽。
- **CSV**：编码要求非空二维稠密数组，各行字段数一致；不支持 NULL 或嵌套单元格。解码不把首行当表头，所有字段返回 string，最多 16384 行。
- **TOML**：根值必须为对象，任何位置都不支持 NULL。
- **INI**：仅支持根层字段和一层 section，值必须为标量；不支持 NULL、数组或更深嵌套。值不能包含换行，名称有字符限制；解码后的值均为 string。
- **XML**：只允许一个根元素；深度最多 32 层、元素最多 16384 个。支持 `_attr`、`_text`，拒绝混合正文与子元素、命名空间名称、DTD 和自定义实体；不支持 NULL。

二进制部分的具体限制：

- format 最长 **8192 字节**；输入数据、打包结果及 packsize 上限为 **1 MiB**。
- position 合法范围为 `[1, #data+1]`，但后续字段仍须有足够数据。
- 整数字段宽度支持 **1～16 字节**，实际数值仍受 Lua 64 位整数范围限制；无符号字段只能使用非负值。
- 浮点字段接受 integer / float；字符串字段只接受 string，可含非 UTF-8 字节。
- `cN` 要求字符串不超过 N 字节，不足补零；`z` 禁止字符串内含零字节；`sN` 的长度前缀宽度为 1～8 字节。
- `!N` 对齐值只能是 1～16 内的二次幂；`binary_packsize` 拒绝 `z`、`sN` 等变长项。

审查中另外发现了 **四处已有问题，本轮未修改**：

1. **signed 多字节解包符号判断错误**：已复现 `<i2` 打包 1000 后，解包得到 **-64536**。
2. **f32 溢出检查缺失**：已复现 `f` 打包有限值 `1e300` 后得到正无限；浮点解包本身也允许 NaN／无限。
3. **对齐后的边界检查缺失**：已在隔离进程复现，对齐后读取 `z` 字段可能触发 **Rust panic**。
4. **部分大小限制检查晚于内存分配**：例如过大的 `cN` 会先扩展缓冲区，1 MiB 限制不能作为分配前的内存保护。

- `reverse` 按 Unicode 字符反转，可能拆开组合字符或多字符 Emoji。

- 支持 `%s、%q、%d、%i、%u、%o、%x、%X、%f、%e、%E、%g、%G、%c、%%`。

- 参数不足报错，多余参数忽略。浮点格式允许 NaN 和正负无限值。

`rich_params` 的值只支持字符串、整数、有限浮点数和布尔值；不支持嵌套表或函数。单项键、值最多 1 MiB，没有独立的总项数限制。

## table

| 方法 | 限制 |
|---|---|
| `concat` | 单次范围最多 16384 项；元素必须为字符串或数字；输出最多 1 MiB |
| `insert` | 插入前数组长度必须小于 16384；位置为 1～数组长度加一 |
| `remove` | 数组长度最多 16384；空表默认返回 nil |
| `sort` | 最多 4096 个数组元素；原地排序，不保证稳定性 |
| `move` | 单次复制最多 16384 项；目标最后写入索引不能超过有符号 64 位整数上限 |
| `pack` | 最多 16384 个参数，包含 nil；返回表另有 `n` 字段 |
| `unpack` | 单次最多展开 16384 个位置；空洞作为 nil 返回，默认结束位置取 `#source` |
| `count / count_array / count_hash` | 输入表顶层实际总项数最多 16384，包含哈希项 |
| `compact` | 正整数键对应的元素最多 16384；哈希项保留，不计入这个上限 |
| `deepcopy` | 最多 32 层，累计复制最多 16384 项；保留循环和共享引用，不复制元表 |
| `pretty` | 最多 32 层、累计遍历 16384 项、输出 1 MiB；循环显示为 `<cycle>` |

另外：

- 这些是**各方法的限制**，并非所有 Lua 表统一限制为 16384 项。例如 `pack` 的 `n` 字段也会计入后续 `count` 的总项数。
- 引擎只读表不能作为写入目标；`move` 省略目标表时会写入源表。
- 原生数组方法沿用 Lua 的 `#`、索引和元方法行为。稀疏表的长度不能当作真实元素数量。
- 自定义比较器应提供一致的排序关系；排序或其他修改操作失败时，不保证恢复原表。
- 整数选项仍接受 `2.0`；`move` 的必填索引还保留 Lua 对数字字符串的整数转换。

`move` 的实际目标边界为：

```text
target_start_index + end_index - start_index ≤ 9223372036854775807
```

现有文档公式比实际边界多加了 1，本次只纠正变量名，未调整该公式。

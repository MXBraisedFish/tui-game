# 格式额外限制笔记

## 一、称呼与书写规范

1. 提到库时，应使用“`库名` 库”来称呼。
2. 提到参数时，应使用“必填参数 `参数名`”或“选填参数 `参数名`”来称呼。
3. 提到返回值时，应使用“返回值”或“返回值 `值名`”（对于多返回值）。
4. 提到方法或常量时，应使用“方法 `方法名`”或“常量 `常量名`”。
5. 所有数字、类型、专门的单词均应使用 `` ` `` 包裹。
6. 所有关于应用本身应使用“程序”称呼。
7. 中英文之间应间隔一个空格，但中文标点符号可以和英文直接衔接。
8. 标点符号应全部使用中文标点符号，且有标记的句子后均有句号结尾。

## 二、数学与取值书写规范

1. 对于参数范围、数学计算必须使用 `$` 来包裹 LaTeX 公式。
2. 取值范围书写时应遵循以下格式：\[参数]取值范围为 \$区间$；（注意此处分割是分号）。
3. 区间存在的特殊情况常见填写如下：
   - 存在变量值：\$变量$ 为（内容解释）。
   - 存在关系值：其中 \$变量A\$、\$变量B\$ ... 和 \$变量n\$ 应当满足公式 \$公式\$ 或（某种关系）。

## 三、格式解释与文档引导

1. 遇到解释格式的必须使用 `lua` 代码块包裹，然后填入表，使用“-- 类型（值含义）”作为注释标记，注释的“--”应当对齐。
2. 文档引导应使用“（前导语）查看⌊\[文档名]\(文档路径)⌉”。

## 四、额外说明的书写原则

1. 所有的额外说明只写一般需要注意的问题。
2. 任何安全问题应列举在未来的安全说明文档中。
3. 一些几乎不可能遇到的边界情况也不写，以减少学习成本。
4. 所有额外说明均应独立完整书写，严谨书写该部分和某个部分相同。

## 五、返回值与参数的类型要求

1. 类型应按照以下顺序排序：
   `string` > `integer` > `float` > `boolean` > `table` > `function` > `const-xxx` > `nil` > 特殊字面量（按照 Unicode 码点排序，必须使用 `` ` `` 包裹书写）。
2. `any` 为所有变量均可，必须为上述除 `const-xxx` 和特殊字面量可不写以外其他参数均可使用时书写。
3. `...` 表示可变参数，以尾缀方式使用。
4. 类型之间使用 `/` 分割（含空格）。
5. 特殊值填写规则：
   - 保持原值直接填写“保持原值”即可。
   - 若使用某个参数或返回值，应使用额外说明中对库、参数和返回值的方式声明。

## 六、返回值的更多格式限制

1. 对于多种情况的返回值必须分情况讨论，并严格按照格式“\*\*xx条件下\*\*，返回X个值。”书写。
2. 直接书写“返回X个值。”，后面不对返回值做解释，该语句作用仅为标记返回什么。
3. 对于表仅标记三种表：对象表（仅存在对象键）、数组表（仅存在数组键）、混合表（三种表都存在）；在额外说明部分强调时也必须严格标记表的类型，而非仅写表。

## 七、规范适用范围

1. 本规范不对 `lifecycle` 库生效。

## 八、参数名和变量名要求

> 该部分也要求工程代码必须同步，而非纯粹仅文档修改。

1. 参数名和变量名应全部使用严谨简写或无意义命名。
2. 所有的参数名和变量名命名语义必须符合英文文化中的专业命名。
3. 简写仅允许出现在该简写命名为 100% 的官方规定和社区认同中（例如 `utf8`、`i18n` 这样的简写）；而例如将 `event` 简写为 `e`、将 `error` 简写为 `err` 这类特别的简写手段是绝对不合法的。
4. 参数名和变量名的命名含义必须唯一；例如多个方法之间都具有相同的参数或变量 `height`，则 `height` 必须具有唯一的意义：元素高度。
5. 如果存在一个方法有额外的含义，必须另起一个命名，避免歧义。
6. 以上对于命名和意义的规范反之依然，意义同样的命名必须一致。

## 四、未纳入机械检查的条款（建议人工过一遍）

以下条款依赖语义判断，脚本无法可靠判定，本次未逐条列出问题：

1. **三.1 格式解释块**：用 `lua` 代码块包裹表格、并以 `-- 类型（值含义）` 注释且 `--` 对齐。请重点看 `date.md`、`timer.md`、`random.md`、`table.md` 里解释返回表的代码块。
2. **六.3 表类型标注**：额外说明中提到「表」时必须写明对象表 / 数组表 / 混合表。
3. **八 参数名与变量名要求**：是否存在 `e`、`err` 这类不被官方或社区认可的简写，以及同名参数在不同方法里语义是否唯一。
4. **四 额外说明的书写原则**：是否只写一般注意事项、是否重复了参数表或其他小节已经说明的内容。
5. **一.5 反引号全覆盖**：脚本只按常见类型词与专有名词做了抽样，其他应当加反引号的单词需人工核对。
6. **二.2 取值范围句末用分号**：规范要求「取值范围为 $区间$；」，部分文档实际以句号结尾，脚本未区分该细节。

## 五、规范本身的待确认点

1. 第二条.1 写「必须使用 `$$` 来包裹 LaTeX 公式」，但第二条.2 的示例与全部文档实际使用的是单个 `$`（如 `$[1, 12]$`）。这两处需要统一，否则无法判定文档是否合规。
2. 模板中没有 `# 目录` 一节，但所有文档都有，且本次检查按「目录必须与正文一致」判定。若目录属于约定俗成的必备结构，建议补进规范模板。
3. 模板规定方法必须有「### 参数」，但没有任何参数的方法目前普遍省略该小节（本次记为「需确认」）。建议在规范中明确无参数方法的写法。
4. 规范未说明存根文档（未开放库）的写法，当前 10 份存根均为「标题 + 两句说明」，未见异常。

## A2 dead-code and dynamic-registration audit

- `EngineServices.file`, `.character_effect`, and `.slice` had no runtime readers and were removed; the Lua file-task route remains because `file` is registered and used. The old stateless `ui`/`unicode` service facades are not restored.
- `RuntimeObjectPoolOwner` and per-page runtime pools remain in use by app routing and widget/time ownership; their presence is not evidence of an unused field by itself.
- `AnimationTargetRouter` remains part of `AnimationService::update_and_apply`; the animation service tests and `animation_smoke` example exercise the public service behavior. No Lua animation library is currently registered.
- The old file-service wrapper is not in `EngineServices`. `FileTask` and `FileEvent` remain for Lua file requests. The host `PathBuf` fields on `FileEvent` have no current runtime reader; retain them pending a service-event contract review because they are public fields. Lua-visible relative paths come from the registered request's `virtual_path`, not those fields.
- `ImageService::convert_async` and its broker operation are not removed: they are not production-reachable today, but B6 explicitly requires an image conversion path and the existing image documentation promises one. D1 records the missing integration.
- Widget event translators and Lua event-callback registration are test-only. Their tests remain; no public production registration was found. D2 and D3 track the documentation/API decision rather than deleting the event types or tests prematurely.
- The remaining items listed in `dev_docs/refactor/history/DEAD_CODE.md` (archived from `temp/handoff/DEAD_CODE.md`) were reviewed against current runtime, test, example, and documentation reachability. Service APIs covered by tests/examples were retained; `ImageService::convert_async` and the event/callback items above are explicitly deferred to their B work packages. This pass did not widen visibility or disable dead-code diagnostics to hide unreferenced code.
